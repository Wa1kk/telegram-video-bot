# Product Requirements Document (PRD)
# Telegram Video Bot

## 1. Обзор продукта

**Название:** Telegram Video Bot  
**Репозиторий:** [Wa1kk/telegram-video-bot](https://github.com/Wa1kk/telegram-video-bot)  
**Версия:** 1.0.0  
**Язык:** JavaScript (Node.js ≥18)  
**Хостинг:** Vercel Serverless Functions  

Telegram-бот, который автоматически скачивает видео и изображения из YouTube, Instagram, Pinterest и TikTok и отправляет их обратно в чат. Бот работает через webhook на Vercel и не требует долгоживущего сервера.

---

## 2. Проблема

Пользователи Telegram часто делятся ссылками на видео из соцсетей, но для просмотра нужно переходить по ссылке и открывать стороннее приложение. Это неудобно, особенно на мобильных устройствах. Существующие боты часто:
- Поддерживают ограниченный набор платформ
- Работают нестабильно из-за блокировок API
- Требуют собственного сервера (VPS)

---

## 3. Целевая аудитория

- Обычные пользователи Telegram, которые хотят смотреть видео прямо в чате
- Администраторы групп и каналов, которые хотят автоматически загружать медиаконтент
- Пользователи из регионов с ограниченным доступом к соцсетям

---

## 4. Функциональные требования

### 4.1 Поддерживаемые платформы

| Платформа | Типы контента | Метод скачивания |
|-----------|--------------|------------------|
| **YouTube** | Shorts, обычные видео | Cobalt API (несколько инстансов) |
| **Instagram** | Посты, Reels, TV, Share-ссылки | GQL + скрейпинг страницы + Cobalt API (fallback) |
| **Pinterest** | Пины (видео и фото) | Скрейпинг `__PWS_DATA__` + og:tags |
| **TikTok** | Видео | Cobalt API (несколько инстансов) |

### 4.2 Основной сценарий использования

1. Пользователь отправляет в чат сообщение, содержащее поддерживаемую ссылку
2. Бот определяет платформу по URL
3. Бот отправляет статусное сообщение: «⬇️ Скачиваю...»
4. Бот скачивает видео/фото и метаданные (название, автор, описание)
5. Бот обновляет статус: «📤 Загружаю в Telegram...»
6. Бот отправляет медиафайл в чат с HTML-подписью (автор, описание)
7. Бот удаляет статусное сообщение

### 4.3 Обработка ошибок

Бот отображает дружественные ошибки на русском языке для типичных ситуаций:
- **Возрастные ограничения** — «❌ Это видео имеет возрастные ограничения.»
- **Приватный контент** — «❌ Это видео приватное.»
- **Удалённый контент** — «❌ Это видео было удалено.»
- **Авторские права** — «❌ Видео заблокировано из-за авторских прав.»
- **Общая ошибка** — «❌ Не удалось скачать видео. Причина: ...»

### 4.4 Поддержка каруселей

Для Instagram-постов с несколькими медиа бот отправляет группу файлов через `sendMediaGroup` (подпись применяется только к первому элементу).

### 4.5 Webhook-безопасность

Опциональная валидация запросов через `X-Telegram-Bot-API-Secret-Token` при наличии `WEBHOOK_SECRET` в окружении.

## 5. Архитектура

### 5.1 Структура проекта

```
├── api/
│   └── webhook.js          # Vercel Serverless Function — точка входа
├── bin/
│   └── yt-dlp              # Бинарник yt-dlp (зарезервирован, не используется в текущей версии)
├── lib/
│   ├── handler.js           # Основной обработчик Telegram-обновлений
│   ├── downloader.js        # Диспетчер платформ (определение + маршрутизация)
│   ├── telegram.js          # Обёртка Telegram Bot API
│   └── platforms/
│       ├── youtube.js       # Скачивание с YouTube через Cobalt
│       ├── instagram.js     # Скачивание с Instagram (GQL + Cobalt fallback)
│       ├── pinterest.js     # Скачивание с Pinterest (скрейпинг)
│       └── tiktok.js        # Скачивание с TikTok через Cobalt
├── scripts/
│   └── setup-webhook.js    # Установка webhook для Telegram
├── .env.example             # Шаблон переменных окружения
├── vercel.json              # Конфигурация Vercel (maxDuration: 300s)
└── package.json
```

### 5.2 Поток данных

```
Telegram → POST /api/webhook → processUpdate()
  → extractSupportedUrls()     # Извлечение URL из entities/regex
  → detectPlatform()           # Определение платформы
  → sendMessage()              # Статус «Скачиваю...»
  → downloadVideo()            # Вызов платформенного модуля
  → editMessage()              # Статус «Загружаю...»
  → sendVideo/sendPhoto/sendMediaGroup()  # Отправка медиа
  → deleteMessage()            # Удаление статусного сообщения
```

### 5.3 Ключевые технические решения

- **Vercel Serverless** — бесплатный хостинг, автоматическое масштабирование
- **Cobalt API** — несколько инстансов с fallback для YouTube и TikTok (обход блокировок)
- **Instagram GQL** — прямой запрос к GraphQL API Instagram с извлечением CSRF-токенов
- **Скрейпинг Pinterest** — парсинг `__PWS_DATA__` из HTML-страницы пина
- **Потоковая загрузка** — файлы скачиваются в `/tmp` и отправляются стримом в Telegram (без хранения)
- **maxDuration: 300s** — увеличенный таймаут Vercel для обработки больших видео

## 7. Переменные окружения

| Переменная | Обязательная | Описание |
|------------|-------------|----------|
| `BOT_TOKEN` | Да | Токен Telegram-бота от @BotFather |
| `WEBHOOK_SECRET` | Нет | Секрет для валидации webhook-запросов |
| `IG_COOKIE` | Нет | Cookie авторизованного Instagram-аккаунта (для доступа к приватным/ограниченным постам) |

---

## 8. Нефункциональные требования

- **Время ответа:** Telegram требует 200 OK в течение ~10 секунд. Бот отвечает после полной обработки (Vercel держит функцию активной до завершения).
- **Лимит файла Telegram:** 50 МБ для ботов (видео большего размера могут не отправиться).
- **Лимит подписи:** 1024 символа (HTML parse_mode).
- **Таймаут Vercel:** 300 секунд (максимальный для Pro-плана).
- **Временные файлы:** Сохраняются в `/tmp`, удаляются после отправки.

---

## 9. Известные ограничения

1. **Размер видео** — Telegram ограничивает отправку файлов до 50 МБ для ботов; длинные видео в высоком качестве не будут отправлены
2. **Cobalt-инстансы** — зависят от сторонних серверов, которые могут быть недоступны или заблокированы
3. **Instagram** — без `IG_COOKIE` некоторые посты могут быть недоступны; Instagram часто меняет структуру страницы
4. **Pinterest** — работает только через скрейпинг, может ломаться при изменениях на сайте
5. **yt-dlp** — бинарник присутствует в репозитории, но не используется в текущей реализации
6. **Один URL** — обрабатывается только первая ссылка из сообщения, остальные игнорируются
